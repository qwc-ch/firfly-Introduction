# AGENTS Documentation

## Overview

`AGENTS.md` provides an overview of the various autonomous agents and tooling available in this DeepSeek Harness project. The agents are designed to assist with code generation, analysis, orchestration, and long‑running goal management.

## Agent Types

| Agent | Description | Typical Use‑Case |
|-------|-------------|-----------------|
| **Subagent** | A lightweight delegated worker that runs a self‑contained task in the background. | Running a quick script, fetching data, performing a single analysis. |
| **Subagent Fork** | Similar to a Subagent but inherits the current conversation context, allowing it to build on prior discussion. | Continuations that need the current conversation history. |
| **Workflow** | A JavaScript orchestrator that coordinates many subagents, tracks phases, and aggregates results. | Large‑scale audits, batch migrations, multi‑angle research. |
| **Ralph** | An isolated iterative fresh‑agent loop with its own memory each round. | Used when the user explicitly requests a Ralph loop for iterative solving. |
| **Goal** | Managed with `create_goal`, `get_goal`, and `update_goal` for multi‑turn objectives. | Complex tasks that span multiple turns. |

## Core Tools

- **`bash`** – Execute shell commands (subject to sandbox policies).
- **`read` / `edit` / `write` / `glob` / `grep`** – File system interactions.
- **`web_search`** – Retrieve up‑to‑date information from the web.
- **`subagent` / `subagent_fork`** – Delegate work to background agents.
- **`workflow`** – Coordinate many subagents and manage phases.
- **`ralph`** – Run isolated iterative loops.
- **Goal management** – Use `create_goal`, `get_goal`, `update_goal` for long‑running tasks.

## Using Agents

1. **Identify the task** – Decide whether a quick subagent, a full workflow, or a goal is appropriate.
2. **Prepare a prompt** – Provide a self‑contained description for subagents, or a full script for workflows.
3. **Invoke the tool** – Use the appropriate tool; background agents run asynchronously and will notify when finished.
4. **Handle results** – When a subagent completes, incorporate its output into the next step or the final answer.
5. **Goal lifecycle** – Create a goal for multi‑turn work, update its status each round with `update_goal`, and mark it `complete` when done.
